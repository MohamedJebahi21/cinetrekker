# Loading diagnosis

Checked against the local Vite app at `http://127.0.0.1:5173` on 2026-11-01 using headless Brave/Playwright. The browser waited for `networkidle`, allowed the app to settle, and scrolled each route to its bottom to trigger deferred and viewport-dependent work. Timings below are browser-observed request durations in this run; they are not service-level guarantees.

| Route | Observed requests | Cause of the earlier blank/skeleton capture | Conclusion |
| --- | --- | --- | --- |
| Home (`/`) | TMDB proxy requests for daily/weekly trending returned HTTP 200 in about 205–324 ms; no matching failed request was observed. | Home discovery is intentionally deferred with `scheduleIdleTask` (up to 1.2 s). The prior capture did not consistently wait for that trigger and its response. `HomeSectionState` does gate this section, but the carousel's own empty state reserves 320–420 px when it is given no items. | No endpoint/API-key/rate-limit/CORS failure reproduced. The first cause is deferred loading and capture timing; the fixed-height empty presentation makes the transient absence look like a permanent blank shelf. |
| Discover (`/discover`) | Trending returned HTTP 200; the deferred movie/TV shelves also returned HTTP 200. In this run, the latter requests took roughly 4.0–4.3 s. No matching failed request was observed. | The page waits 800 ms before enabling most shelf queries. It does not pass each query's `isLoading`, `isError`, or retry callback to `MediaSection`, so a slow shelf is represented as an empty carousel rather than a bounded loading/error state. Cards also use `content-visibility: auto`, so scrolling is necessary to verify off-screen rendering. | Slow successful provider responses plus missing per-shelf loading/error wiring; no lazy-import or endpoint defect reproduced. The wait-and-scroll capture loaded the shelves. |
| TV detail (`/tv/mobland-247718`) | The TV detail, similar-titles, and provider endpoints returned HTTP 200; detail data took about 4.0 s. Season 2 returned HTTP 200 in about 200 ms after it was requested. No matching failed request was observed. | The original screenshot was taken before the detail request completed. Detail loading already has a 15 s timeout with an error/retry route, but episode loading has `retry: false` and renders a spinner whenever `seasonDetails` is absent, without checking the query's error state. | The full-page skeleton was slow successful loading, not a missing title or invalid API key. The episode spinner was transient in this run; however, a genuine season-request error can leave that spinner indefinitely because the error is not rendered. |

## Evidence limits

- HTTP 200 confirms the browser received successful proxy responses; it does not, by itself, guarantee that every response contains a non-empty result array. The settled-and-scrolled browser pass displayed title cards on the shelves that had results.
- The 99-image after matrix includes all 11 discovered routes at 375/768/1440 px and light/dark/OLED. The full-page screenshot tool returned to scroll position zero before capture; because carousel cards use `content-visibility: auto`, later off-screen cards were omitted from the full-page image. A separate viewport capture with the Discover shelf actually in view shows five fully rendered posters and its pagination (`design-review/after/discover-scrolled-trending-viewport.png`). This is a capture limitation, not a live blank-shelf regression.
- Browser requests aborted during route changes in the earlier screenshot matrix are capture cancellations and are not counted here as provider failures.
- In the after matrix, one local `/search/movie` proxy request returned HTTP 500 and a `/search/tv` request was aborted during navigation; the searched results still rendered from subsequent/available responses. Treat this as an intermittent local search-service failure to investigate separately. The YouTube thumbnail HTTP 404 and service-worker registration warnings came from the test environment / remote trailer thumbnail and did not prevent route rendering.
- No endpoint, model, authentication, or data-contract changes are justified by the observed run. The UI should handle slow responses and actual errors explicitly, and should not reserve carousel space when there are no items.
