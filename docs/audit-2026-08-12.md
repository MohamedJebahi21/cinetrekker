# CineTrekker — Full Codebase Audit

_Date: 2026-08-12. Read-only audit; no files were modified during the review._

**Scope:** 260 TS/TSX files (~50k lines) across the React/Vite frontend, `api/` Vercel serverless functions, Supabase edge functions + 21 SQL migrations, TMDB integration, and build config. All findings were verified against source by seven parallel review passes.

**Overall health:** Genuinely good bones. RLS is enabled on every user table with correct `auth.uid() = user_id` checks, `SECURITY DEFINER` RPCs derive the user from the session (never a param), no service-role/private key is exposed to the client, routes are lazy-loaded, the shared `Image` component and `MediaCard` are exemplary, and JSON-LD injection is XSS-hardened via Trusted Types. The issues below are real but sit on a solid foundation.

## Top priorities (fix-first shortlist)
1. **UserProfile shows the *wrong* user's watch history** — correctness **and** privacy leak (Bugs #1)
2. **Settings silently discards unsaved edits** on async/realtime load — data loss (Bugs #2)
3. **Follows list can disable itself permanently** across reloads (Bugs #3)
4. **Unauthenticated forge of notifications for any user** — broken RLS (Security #1)
5. **`Search` filter panel remounts every render** — closes popovers, drops focus (Bugs #4 / Perf)
6. **Calendar's main interaction is keyboard-unreachable** (Accessibility #1)

## 1. Bugs & errors

**Critical**
- **`src/pages/UserProfile.tsx:24,62-69,198-247`** — The page fetches the *target* user's profile but reads `watched` from `useUserLists()`, which is the **logged-in** user's data. Stats and the "Recently Watched" grid on anyone's public profile show *your* history (logged-out → all zeros). *Wrong data + a privacy leak.*
- **`src/pages/Settings.tsx:352-372`** — `apply()` unconditionally `setSettings`/resets the baseline/clears `hasUnsaved` on initial load, async fetch resolve, **and** realtime pushes, with no guard for pending edits. A slow fetch or another-device update clobbers in-progress toggles. *Data loss.*
- **`src/hooks/useTitleFollows.ts:363` (+49,57-79)** — The follows query is gated on `!followStateSchemaMissing`, a flag **persisted to localStorage** whenever the *optional* `followed_title_state_user` table is missing — but the query reads unrelated healthy tables. Once tripped, the followed shows/movies list is empty forever across reloads.

## 2. Security

**Moderate**
- **`supabase/migrations/20260312090000_...:98-101`** (dup in `20260317153000_...:109-116`) — `notifications` INSERT policy is `WITH CHECK (auth.uid() IS NULL)`. The service role bypasses RLS anyway, but the **anon** role also has `auth.uid() = NULL` and default table grants, and nothing ties the row's `user_id` to the caller → **anyone with the public anon key can forge notifications (arbitrary user, type, message) for any user.** _Drop this policy; rely on the existing `notifications_insert_own`._
- **`api/tmdb-proxy.js:147-243`** — The production TMDB proxy path performs **no** origin check, rate limit, or auth (unlike every other function), forwarding arbitrary TMDB paths with the server's `TMDB_API_KEY`. SSRF is blocked by path validation, but it's a free anonymous relay on your key/compute.
- **`api/recommend.js:31-63`** — Unauthenticated OpenAI-backed endpoint (plus TMDB calls per request), gated only by a spoofable `Origin` allowlist and a per-instance IP limit → billing-abuse vector. _Consider requiring auth or a captcha as `feedback.js` does._
- **`src/hooks/useTrendingSignals.ts:15-20`** — Query deliberately omits `.eq('user_id')`; under RLS it silently returns only the caller's rows (trending is wrong), or if it returns others' rows, RLS is missing on `user_watchlist`. _Confirm the policy._

**Minor**
- `api/_lib/requestSecurity.js:32-36,87-104` — rate limiting is in-memory per instance unless Upstash is configured; real-world limits are much weaker than documented.
- `api/_lib/requestSecurity.js:56-73` & `supabase/functions/tmdb-proxy/index.ts:244` — origin allowlist treated as access control; the edge proxy explicitly lets empty-`Origin` requests through (only blocks browsers).
- `scratch/test-edge.js:1-2`, `scratch/test-signup.js:3-4` — committed Supabase URL + anon key (public key, so not a true leak, but `scratch/` shouldn't be in the repo).
- `src/components/ShareButton.tsx:85` — `window.open(url, '_blank')` without `noopener` (reverse-tabnabbing). _This is the only noopener gap; all `<a target="_blank">` are correct._
- `vercel.json:101` — CSP allows `style-src 'unsafe-inline'` and `img/media-src https:` (scripts are well locked down).
- `followed_title_state` was created without RLS for its lifetime (later dropped in `20260613170000`) — confirm the drop is applied in prod.

**Verified safe:** no service-role key in `src/` or `dist/` (only the anon JWT); `edge-meta.js` redirects same-origin only; `feedback.js` fails closed on missing captcha; all `SECURITY DEFINER` RPCs are `REVOKE`d from PUBLIC / `GRANT`ed to `authenticated`; authenticated serverless routes reject `user_id` mismatch.

## 3. Performance

**Critical**
- **`src/pages/Profile.tsx:211,275`** — A single 3,332-line component with ~25 `useState`s, carousels, and charts re-renders wholesale on every keystroke in the bio/name fields, while `humanizeUiText` (regex + 6 chained `.replace()`) runs 80+ times per render, unmemoized.

**Moderate**
- **Bundle** (`vite.config.ts` / `dist/`): framer-motion (127 KB) sits on the initial critical path — move to `LazyMotion`; `vendor-ui` is a 247 KB monolith of 30+ Radix packages loaded eagerly; recharts ships as one 391 KB `PieChart-*` chunk and the `vendor-charts` module-preload deferral is **dead config** because no such chunk is produced; initial JS ≈1 MB raw / ~300–350 KB gzip.
- **`src/pages/Profile.tsx:1074-1133,1023-1072`** — N+1 fan-out: up to 120+ TMDB detail requests fired on page load to build stats.
- **`src/pages/Calendar.tsx:110,327`** — `todayStart = startOfDay(new Date())` is a fresh reference each render and is a dep of the `calendarItems` memo, so the expensive merge/dedup/group never caches; the search box isn't debounced. _Fix: `useMemo(() => startOfDay(new Date()), [])`._
- **`src/pages/Details.tsx:592-700`** — Crew filters, an O(n²) recommendations dedup, and `heroFacts` are recomputed every render while two IntersectionObservers re-render the page on scroll.
- **`src/pages/Settings.tsx:311-314`** — `text()`/`humanizeUiText` runs 50+×/render, including every font-size slider tick.
- **`src/pages/Achievements.tsx:889-918`** — A 30-line `tierStyles` object is reallocated per card, per render, inside `.map`.
- **`src/pages/Search.tsx:960-1026`** — Option arrays and `activeFilterPills` (O(n·m)) recomputed unmemoized each render.
- **`src/pages/Person.tsx:106-133,~50-57`** — `movies`/`tv`/`directed`/`notable` filtered+sorted every render (no memo); parallax scroll writes `transform` synchronously with no rAF throttle.
- **`src/pages/Watchlist.tsx:145-202`** — `filteredMedia`, dates map, `sortMedia`, `statusCounts`, `totalRuntimeMinutes` all recomputed unmemoized.
- **`src/pages/Discover.tsx:~199-247`** and **`src/pages/AwardWinners.tsx:150,193,235`** — 10 and 3 `useQuery`s respectively fire on mount with no `enabled` gating/staggering; AwardWinners actor search has no debounce (one request/keystroke).
- **`src/components/MediaComments.tsx` (CommentCard)** — not `React.memo`'d; every card re-renders per keystroke in the new-comment box.
- **`src/components/details/MediaGallery.tsx:134`** — up to 6 eager YouTube `<iframe>`s, no `loading="lazy"`.
- **`src/components/TVWatchStatusModal.tsx:60-69`** — sequential `await`-in-loop season fetch (N round-trips) instead of `Promise.all`.
- **`src/components/SearchDropdown.tsx`** — `results` recomputed via `applySafetyFilter` each render, which defeats the `handleKeyDown` `useCallback`.

**Minor:** 207 KB single render-blocking CSS bundle; `UnifiedNav.tsx:416,578` avatar `<img>` missing `width/height/loading` (CLS); `html-to-image` is an unused dependency; `src/components/ui/chart.tsx` is dead and does `import * from 'recharts'` (latent 391 KB footgun).

## 4. Code quality

**Moderate**
- **Monolithic page components** — Profile (3332), Details (1631), Search (1543), Calendar (1411), Settings (1122), Achievements (1114), EnhancedStats (968) each mix data-fetching, transforms, multiple views, and dialogs in one file. Extract `use*Data`/`use*Form` hooks + view subcomponents; the whole-tree re-render is the single biggest structural issue.

## 5. Accessibility

**Critical**
- **`src/pages/Calendar.tsx:870,1107,1231`** — The primary "open details" targets are bare `<div onClick>` with no `role="button"`, `tabIndex`, or key handler → the main content of the Calendar route is entirely unreachable by keyboard/screen-reader users.

**Moderate**
- **`src/components/TrailerModal.tsx`** — custom dialog with `aria-modal="true"` but no focus move-in, no focus trap, no focus restore (misrepresents behavior; focus escapes to the page behind).
- **`src/components/UnifiedNav.tsx:442-448`** — desktop "Menu" overlay declares `aria-modal` but has no focus trap and no Escape handler (the mobile menu correctly uses a Radix `Sheet`).
- **`src/components/UnifiedNav.tsx:501-508,646-660`** — active nav links convey state only visually; missing `aria-current="page"` (`MobileBottomNav` does this right).
- **`src/lib/accessibility-preferences.ts:60-74`** — the in-app **Reduce Motion** setting only toggles a CSS class, but framer-motion animations gate on `useReducedMotion()` (OS media query only) and there's no `MotionConfig`, so the setting doesn't stop carousels/tilt/staggered reveals.
- **`src/components/MediaComments.tsx:119-124`** — spoiler reveal is a click-only `<p>` (no keyboard, no touch path).
- **`src/components/UserProfileDropdown.tsx:147-156`** — the identity header inside the Radix menu is a `<div onClick>` (not a menu item) → mouse-only.
- **`src/components/ShareButton.tsx`** — custom `role="menu"` whose items lack `role="menuitem"`, no arrow-key nav / Escape / focus trap; trigger missing `aria-haspopup`/`aria-expanded`.
- **Dark-theme contrast** (systemic, fix at the token level): `text-muted-foreground/60` ≈ **3.5:1** on meaningful small labels (EnhancedStats, Recommendations, ActorMatchesSection…); primary red `hsl(356 84% 50%)` ≈ **4.3:1** and `.ct-kicker` uses `text-primary/70` (below AA); `tailwind.config.ts:41` wraps `--muted-foreground` in `0.7` alpha → ≈**4.4:1** for the most common secondary-text color app-wide.

**Minor:** Achievements per-card share button has no `aria-label`; hero carousel has no keyboard pause / `aria-live` (`HeroSection.tsx:47-53`); mobile home has no `<h1>` (desktop `<h1>` is `hidden md:block`); posters fall back to `alt=""` when the title is missing (`Discover.tsx:167`, `Watchlist.tsx:550`, `Person.tsx:342`); `Image.tsx:105` forwards possibly-undefined `alt`; `Details.tsx:172` can announce "Play undefined"; `GlassStatCard` always shows `cursor-pointer`; `OnboardingTooltip` custom overlay isn't `role="dialog"` and has no focus management.

_Good: working skip link, focusable `<main>`, extensive `:focus-visible` styles, `lang`/`dir` synced on language change, well-labeled forms, Radix dialogs/menus._

## 6. TypeScript hygiene

**Moderate**
- **`tsconfig.json` / `tsconfig.app.json`** — `strict` is on (good), but `noUncheckedIndexedAccess` is **off**; given heavy array/`Record`/Map access on TMDB data, out-of-bounds reads type as defined and crash at runtime. Highest-value flag not yet enabled.
- **Unused-code checking is fully off** — `eslint.config.js:23` sets `@typescript-eslint/no-unused-vars: "off"`, and tsconfigs don't set `noUnusedLocals`/`noUnusedParameters` (node config sets them `false`). This is why dead imports and the unused `html-to-image` dep accumulate silently.
- **`src/services/tmdb.ts:658`** — `PersonDetails` has `[key: string]: any`, so every property access on this core domain type resolves to `any` (typos compile). The most dangerous single type hole in `src/`.
- **`src/services/profile.ts:139,154,190`** — insert/update payloads cast `as any`, result cast back `as UserProfile`; the generated DB types never validate writes (exactly where schema drift bites). `src/services/social.ts:41-43,79` casts the client to a loose interface, opting the whole service out of generated types.
- **`src/services/tmdb.ts:126-153`** — `fetchTMDB<T>` returns unvalidated network JSON as `T` with no runtime check (zod is already a dependency but unused here).

**Minor:** `no-explicit-any` is only a warning and `eslint .` exits 0 on warnings, so CI doesn't block new `any`; nine `as unknown as` double-casts (notably `SearchDropdown.tsx:211,214`, `ActorMatchesSection.tsx:345` reshaping TMDB arrays); `@ts-expect-error` at `Search.tsx:723` papers over a real mixed-media-union gap; no enforced return types on exported service/hook functions; `Details.tsx` loose typing (`getPolicyRatingTag(details: unknown)`, `(error as Error)`); `Search.tsx:420,461` casts `type` from the URL with no validation; several Supabase results asserted as non-null arrays without `?? []` guards (`useFollowedShows.ts:137,227`, `useTitleFollows.ts:392,401`, `useNotifications.ts:210`); `MediaGrid` `containerVariants` untyped.

## Rough triage suggestion
- **Now:** Bugs #1–3, Security #1, #2, #4 — correctness/privacy/abuse with real user impact.
- **Next:** the `Search`/`Settings`/`Discover` state bugs, Calendar keyboard access (A11y #1), and the dark-theme contrast tokens (systemic, cheap at the config level).
- **Then:** the perf/bundle wins (LazyMotion, split `vendor-ui`, fix the recharts chunk, memoize the hot pages) and the two TS strictness flags.
- **Ongoing:** splitting the monolith pages and closing the i18n gap — larger refactors, best done incrementally.
